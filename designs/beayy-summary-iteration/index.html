设计稿 · 总结功能迭代

让总结不只是「一天的流水」，而是「你和自己的承诺」

本文档基于对 crates/timeseen-summary、src-tauri/src/daily.rs、ui/app.js 总结页的深入阅读。它给出分析、迭代路线图、以及每个迭代的 UI 设计稿。所有视觉沿用墨线（moxian）令牌与现有组件，落地时直接写进 ui/style.css / ui/app.js，不需要新设计系统。

01现状分析

先看清楚现在这条链路能做什么、卡在哪里，再决定迭代顺序。

数据链路

10 分钟分段摘要→ 小时 rollup→ 日总结（21:30 / 次日 0:15）→ 周视图→ 明天承诺 → 待办

分段由 summarizer.rs 每 10 分钟调度；日总结由 daily.rs 用当天 get_day 的统计喂给模型；页面 renderSummary 渲染并把「明天」写回待办。

三个结构性缺口

① 承诺没有回流

昨天「明天」写的待办，今天生成日总结时只带未完成待办，不带昨日承诺。于是「昨天答应、今天没做」永远不会出现在 drift 里，承诺闭环在模型那一步断了。

② 只有日 / 周，没有月

月 tab 写着「先不做月」。日与日之间缺一层，看不出「这个月我到底把时间花在了哪几个项目上」「规矩这月守住几天」。

③ 数字全，但结论弱

时长、切换、规矩都有，但缺节奏（碎片度、连续专注、拿起间隔）和跨期对比（vs 上周）。模型只能写「今天用了 X 小时」，写不出「今天下午切换了 87 次」。

次要缺口

  • 模型返回坏 JSON 时整篇失败，无降级；总结生成后不可编辑。
  • AI 关掉就完全没有日总结，缺「本地版」。
  • 「明天」条目的「约 25 分钟」是写死的（ui/app.js:1123）。
  • 规矩引擎只认「几点以后」和「每天不超过 N 分钟/小时」，算不出来的在页面没有提示。

02迭代路线图

四个阶段，每阶段独立可交付、不互相阻塞。顺序按「收益 / 改动量」排。

1

承诺回流与节奏洞察 先做

改动小 · 逻辑缺口 · 不新增页面

  • 昨日承诺回流：日总结 prompt 增加「昨天承诺的 N 条做成了几条」，让 drift 能写「昨天答应的 X 没做」。
  • 节奏洞察：从原始事件算碎片度（每小时切换次数）、最长连续专注、手机拿起间隔，作为固定字段喂模型。
  • 10 分钟摘要承接上文：把上一段摘要前 100 字带进 prompt，小时 rollup 更连贯，减少逐段重复。
2

周视图对比 + 总结可编辑 次做

中等 · 现有页面增强

  • 这周 vs 上周：在电脑前、熬夜、项目时长、承诺兑现率，各加一个 delta 读数。
  • 总结可编辑：生成后可就地编辑 markdown，存为最终版，覆盖自动生成。
  • JSON 容错：模型返回坏 JSON 时自动修复重试一次，仍失败则降级纯文本渲染。
3

月视图 可后做

中等 · 新视图

  • 月历：每天一句话 + 项目月度合计条形 + 规矩月度守住率。
  • 项目月度排行：跨天聚合，回答「这个月时间花在哪几个项目」。
4

回看搜索 + 本地版 + 规矩引擎 远期

较大 · 新功能

  • 全文搜索：按关键词 / 项目 / 日期搜所有日总结 markdown。
  • 本地版总结：AI 关掉也能出纯统计 + 模板文字。
  • 规矩引擎扩语法：工作日/周末、每周不超过、每次不超过，算不出来给提示。
落地顺序：1 → 2 → 3 → 4。1 和 2 可合并成一个版本；3、4 各自独立。

03设计规范

全部沿用墨线令牌，不引入新色板。新增只做「结构」，不做「皮肤」。

读数卡

沿用 .readout：键小字灰、值大字重、副注更小。新读数（碎片度、连续专注）放进同一套。

delta 徽标

新增 .delta：绿升红降灰平，紧跟读数右侧，回答「比上周怎样」。颜色语义与规矩 ✓/✗ 一致。

承诺行

沿用 .cmt 勾选行，「约 25 分钟」改为可编辑 .cmt-meta，默认按项目近期时长估算。
